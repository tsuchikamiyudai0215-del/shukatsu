# GAS の準備と、開発用シートでの移行

開発中は、開発用のシート・カレンダー・Drive フォルダだけを使う。本番のシート（ID が `1v-nnIz3` で始まるもの）と既定のカレンダーには触らない。

コードにも安全装置がある。

- `SHEET_ID` が本番のシートを指していたら開かない
- `CALENDAR_ID` が既定のカレンダーを指していたら使わない
- `CalendarApp.getDefaultCalendar()` は使わない
- 別のカレンダーの予定を指す ID を見つけても、その予定には触らない
- 移行のとき、旧版のカレンダー予定の ID は引き継がない（開発用シートの中の ID は本番のカレンダーの予定を指しているため）

この安全装置は、スクリプトのプロパティ `ALLOW_PRODUCTION` を `yes` にすると外れる。本番に切り替える日（7章の手順5）まで、`ALLOW_PRODUCTION` は置かない。

## 1. clasp にログインする

`v2/` で次を実行する。ブラウザが開くので、開発用シートを持っている Google アカウントを選んで許可する。

```
npx clasp login
```

## 2. GAS のプロジェクトを作る（シートに結びつけない）

```
npx clasp create-script --type standalone --title "就活ボード v2（開発）" --rootDir gas
```

`v2/.clasp.json` ができる（公開リポジトリには置かないので `.gitignore` に入れてある）。
このとき `gas/appsscript.json` が作ったばかりのプロジェクトの中身で上書きされるので、git で元に戻してから送る。

```
git checkout -- gas/appsscript.json
npm run push
```

`npm run push` は、`shared/domain.js` を `gas/` へ写して（`npm run sync`）から `clasp push --force` を行う。
`--force` を付けないと、向こうの `appsscript.json` と違うときに確認を求めて止まる（ターミナルからは答えられず「Skipping push.」になる）。
`appsscript.json` はリポジトリの方を正しいものとして、毎回そちらで上書きする。

## 3. 開発用の Drive フォルダを作る

1. [Google ドライブ](https://drive.google.com/) を開く
2. 左上の「新規」→「新しいフォルダ」
3. 名前を「就活ボード v2 開発用」にして「作成」
4. できたフォルダを開く。アドレスバーの `https://drive.google.com/drive/folders/` のあとの文字列がフォルダの ID

本番のフォルダ（旧版の企業フォルダが入っている親フォルダ）の中には作らない。

## 4. スクリプトのプロパティを入れる

鍵（`API_KEY`）は長いランダムな文字列にする。`v2/` で次を実行すると作れる。出てきた文字列は画面の接続設定でも使うので、パスワード管理アプリなどに控えておく。

```
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

1. `npx clasp open-script` でエディタを開く
2. 左の歯車「プロジェクトの設定」→ いちばん下の「スクリプト プロパティを追加」
3. 次の4つを入れて「スクリプト プロパティを保存」

| プロパティ | 値 |
|---|---|
| `SHEET_ID` | 開発用シートの ID |
| `CALENDAR_ID` | 開発用カレンダーの ID |
| `DRIVE_PARENT_ID` | 3 で作ったフォルダの ID |
| `API_KEY` | 上で作った鍵 |

## 5. 設定を確かめる（初回は権限の許可が出る）

1. エディタ上部の関数の選択で `checkSetup` を選び「実行」
2. 「承認が必要です」→「権限を確認」→ アカウントを選ぶ
3. 「このアプリは Google で確認されていません」と出たら「詳細」→「就活ボード v2（開発）（安全ではないページ）に移動」→「許可」。自分で作ったスクリプトなので、この表示が出るのは普通
4. 実行ログに、シート名・カレンダー名・フォルダ名と「本番への切り替え：オフ（開発中）」が出れば準備完了

## 6. 開発用シートで migrate() を動かす

### 6-1. 開発用シートの控えを作る

1. 開発用シートを開く
2. 「ファイル」→「コピーを作成」
3. 名前を「就活シート（開発用）移行前の控え」にして「コピーを作成」
4. 控えは開かずにそのまま置いておく

開発用シートは本番のコピーなので、旧版のスクリプトもついてきている。その中には本番シートの ID が書いてあるので、**開発用シートや控えの「📋 就活管理」メニューは押さない**（押すと本番シートを書き換えるものがある）。

### 6-2. 移行する

1. エディタで `migrate` を選んで「実行」
2. 実行ログに「移行しました：会社 ○ 件、予定 ○ 件」と出る。
   「会社が見つからない予定」「日時が読めない予定」があれば、件数と名前も出る
3. 開発用シートに `companies` と `events` の2枚が増えている。旧版の `Sheet1` と `予定` はそのまま

移行で行うこと

- 状態は「状態」列から決める（空なら I列から）。夏インターンの「内定」は参加決定
- 日付・時・分を `dueAt` にまとめる（時が空なら、その日いっぱいの締切）
- フォルダの数式から URL を取り出す
- D列のパスワードを `pw` 列へ移す
- 予定は会社名＋区分で会社を探し、`companyId` でつなぐ
- 結果発表の予定日（N列）は移さない（機能ごと外した）

### 6-3. カレンダーを合わせる

1. エディタで `syncAllCalendars` を選んで「実行」
2. 開発用カレンダーに、対応中の会社の締切と、予定タブの予定ができる
3. 実行ログに「まだ ○ 社残っています」と出たら、もう一度実行する（続きから進む）

### 予定が思ったとおりにできないとき

エディタで `inspectCalendar` を実行する。何も書き換えずに、各社の状態・締切・あるべき予定・今の対応表と、開発用カレンダーにある予定の一覧を実行ログに出す。パスワードは出さない。

### やり直すとき

開発用シートの `companies` と `events` の2枚を消してから、6-2 からやり直す。開発用カレンダーにできた予定は、カレンダーごと消して作り直すのが早い（カレンダーの ID が変わるので `CALENDAR_ID` も入れ直す）。
シートそのものを戻したいときは、6-1 の控えをもう一度コピーして使い、`SHEET_ID` をその ID に変える。

## 本番に切り替えるとき（7章の手順5。今はまだやらない）

- `SHEET_ID` を本番シート、`CALENDAR_ID` を既定のカレンダー（自分の Gmail アドレス）、`DRIVE_PARENT_ID` を旧版の親フォルダにし、`ALLOW_PRODUCTION` を `yes` にする
- 旧版のロゴの記録を移すなら、`LEGACY_LOGOS` に JSON で入れる
- `migrate()` は、このときだけ旧版のカレンダー予定の ID を引き継ぎ、作り直さない。結果発表の予定は引き継がず、説明欄のパスワードの行だけを消す
- 続けて `syncAllCalendars()` を実行すると、引き継いだ予定の説明欄からもパスワードが消える

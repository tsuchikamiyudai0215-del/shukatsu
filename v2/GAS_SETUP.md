# GAS の準備と、開発用シートでの移行

開発中は、開発用のシート・カレンダー・Drive フォルダだけを使う。本番のシート（ID が `1v-nnIz3` で始まるもの）と既定のカレンダーには触らない。

コードにも安全装置がある。

- `SHEET_ID` が本番のシートを指していたら開かない
- `CALENDAR_ID` が既定のカレンダーを指していたら使わない
- `CalendarApp.getDefaultCalendar()` は使わない
- 別のカレンダーの予定を指す ID を見つけても、その予定には触らない
- 移行のとき、旧版のカレンダー予定の ID は引き継がない（開発用シートの中の ID は本番のカレンダーの予定を指しているため）

この安全装置は、スクリプトのプロパティ `ALLOW_PRODUCTION` を `yes` にすると外れる。本番に切り替える日（7章の手順5）まで、`ALLOW_PRODUCTION` は置かない。

## 1. clasp にログインする

`v2/` で次を実行する。ブラウザが開くので、開発用シートを持っている Google アカウントを選んで許可する。

```
npx clasp login
```

## 2. GAS のプロジェクトを作る（シートに結びつけない）

```
npx clasp create-script --type standalone --title "就活ボード v2（開発）" --rootDir gas
```

`v2/.clasp.json` ができる（公開リポジトリには置かないので `.gitignore` に入れてある）。
このとき `gas/appsscript.json` が作ったばかりのプロジェクトの中身で上書きされるので、git で元に戻してから送る。

```
git checkout -- gas/appsscript.json
npm run push
```

`npm run push` は、`shared/domain.js` を `gas/` へ写して（`npm run sync`）から `clasp push --force` を行う。
`--force` を付けないと、向こうの `appsscript.json` と違うときに確認を求めて止まる（ターミナルからは答えられず「Skipping push.」になる）。
`appsscript.json` はリポジトリの方を正しいものとして、毎回そちらで上書きする。

## 3. 開発用の Drive フォルダを作る

1. [Google ドライブ](https://drive.google.com/) を開く
2. 左上の「新規」→「新しいフォルダ」
3. 名前を「就活ボード v2 開発用」にして「作成」
4. できたフォルダを開く。アドレスバーの `https://drive.google.com/drive/folders/` のあとの文字列がフォルダの ID

本番のフォルダ（旧版の企業フォルダが入っている親フォルダ）の中には作らない。

## 4. スクリプトのプロパティを入れる

鍵（`API_KEY`）は長いランダムな文字列にする。`v2/` で次を実行すると作れる。出てきた文字列は画面の接続設定でも使うので、パスワード管理アプリなどに控えておく。

```
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

1. `npx clasp open-script` でエディタを開く
2. 左の歯車「プロジェクトの設定」→ いちばん下の「スクリプト プロパティを追加」
3. 次の4つを入れて「スクリプト プロパティを保存」

| プロパティ | 値 |
|---|---|
| `SHEET_ID` | 開発用シートの ID |
| `CALENDAR_ID` | 開発用カレンダーの ID |
| `DRIVE_PARENT_ID` | 3 で作ったフォルダの ID |
| `API_KEY` | 上で作った鍵 |

## 5. 設定を確かめる（初回は権限の許可が出る）

1. エディタ上部の関数の選択で `checkSetup` を選び「実行」
2. 「承認が必要です」→「権限を確認」→ アカウントを選ぶ
3. 「このアプリは Google で確認されていません」と出たら「詳細」→「就活ボード v2（開発）（安全ではないページ）に移動」→「許可」。自分で作ったスクリプトなので、この表示が出るのは普通
4. 実行ログに、シート名・カレンダー名・フォルダ名と「本番への切り替え：オフ（開発中）」が出れば準備完了

## 6. 開発用シートで migrate() を動かす

### 6-1. 開発用シートの控えを作る

1. 開発用シートを開く
2. 「ファイル」→「コピーを作成」
3. 名前を「就活シート（開発用）移行前の控え」にして「コピーを作成」
4. 控えは開かずにそのまま置いておく

開発用シートは本番のコピーなので、旧版のスクリプトもついてきている。その中には本番シートの ID が書いてあるので、**開発用シートや控えの「📋 就活管理」メニューは押さない**（押すと本番シートを書き換えるものがある）。

### 6-2. 移行する

1. エディタで `migrate` を選んで「実行」
2. 実行ログに「移行しました：会社 ○ 件、予定 ○ 件」と出る。
   「会社が見つからない予定」「日時が読めない予定」があれば、件数と名前も出る
3. 開発用シートに `companies` と `events` の2枚が増えている。旧版の `Sheet1` と `予定` はそのまま

移行で行うこと

- 状態は「状態」列から決める（空なら I列から）。夏インターンの「内定」は参加決定
- 日付・時・分を `dueAt` にまとめる（時が空なら、その日いっぱいの締切）
- フォルダの数式から URL を取り出す
- D列のパスワードを `pw` 列へ移す
- 予定は会社名＋区分で会社を探し、`companyId` でつなぐ
- 結果発表の予定日（N列）は移さない（機能ごと外した）

### 6-3. カレンダーを合わせる

1. エディタで `syncAllCalendars` を選んで「実行」
2. 開発用カレンダーに、対応中の会社の締切と、予定タブの予定ができる
3. 実行ログに「まだ ○ 社残っています」と出たら、もう一度実行する（続きから進む）

### 予定が思ったとおりにできないとき

エディタで `inspectCalendar` を実行する。何も書き換えずに、各社の状態・締切・あるべき予定・今の対応表と、開発用カレンダーにある予定の一覧を実行ログに出す。パスワードは出さない。

### やり直すとき

開発用シートの `companies` と `events` の2枚を消してから、6-2 からやり直す。開発用カレンダーにできた予定は、カレンダーごと消して作り直すのが早い（カレンダーの ID が変わるので `CALENDAR_ID` も入れ直す）。
シートそのものを戻したいときは、6-1 の控えをもう一度コピーして使い、`SHEET_ID` をその ID に変える。

### 6-4. 旧版のロゴの記録を取り込む

旧版のロゴの記録は、リポジトリの一番上の `legacy-logos.json`（会社名 → URL）に置く。このファイルは `.gitignore` に入れてあり、commit しない。
GAS からは手元のファイルを読めないので、中身をスクリプトのプロパティに貼ってから取り込む。

1. `legacy-logos.json` をエディタで開き、中身を全部コピーする（1行の JSON）
2. プロジェクトの設定 → スクリプト プロパティに `LEGACY_LOGOS` を足し、値に貼って保存する。1つの値は 9KB まで入る
3. エディタで `migrate.gs` を開き、`importLegacyLogos` を選んで「実行」

取り込みの決まり

- 会社名で companies の行と対応させる。同じ名前の行（夏インターンと本選考）には全部入れる
- logo 列が空か、画面が自動で見つけたもの（logoManual が FALSE）だけを上書きする。手で入れたものは残す
- https:// で始まらない値（テストセンターの「SPI３」など）は入れない
- 伊藤忠テクノソリューションズと履修データセンターは、建物の写真なので入れない
- 対応する行が無かった会社名は、実行ログに出す
- 何度実行してもよい。`updatedAt` もカレンダーも変えない

`LEGACY_LOGOS` が入っていれば、`migrate()` でも同じ決まりでロゴを入れる。本番に切り替えるときは、`migrate()` のあとに `importLegacyLogos()` を実行しても同じ結果になる。

画像ファイルから入れた手動のロゴは、旧版の画面の端末保存（`sk_manual_logos`）にある。これは新版の画面を github.io で初めて開いたときに、一度だけ新版の保存へ写す（旧版の保存は消さない）。画像ファイルはその端末にだけ、URL はシートにも手動として入る。

### 6-5. パスワードが空の会社に、同じパスワードをまとめて入れる

pw 列が空の行にだけ書き、すでに入っている行と管理用の行（テストセンターなど）は触らない。
パスワードの文字列は、commit するファイル・commit メッセージ・実行ログのどこにも残さない。

1. `v2/gas/` に一時ファイル `fill-password.local.js` を作る。`*.local.js` は `.gitignore` に入れてあるので、git には入らない

   ```js
   function fillEmptyPasswords() {
     fillEmptyPasswords_('ここに入れたいパスワード');
   }
   ```

2. `npm run push` で送る（clasp は `.gitignore` を見ないので、一時ファイルも送られる）
3. エディタを再読み込み（F5）し、`fill-password.local.gs` を開いて `fillEmptyPasswords` を選び「実行」
4. 実行ログには「パスワードが空だった ○ 社に入れました。」とだけ出る
5. すぐに一時ファイルを消し、`npm run push:clean` で送り直す。
   `npm run push` では消えない。clasp は手元にあるファイルだけを比べて「もう最新」と判断し、何も送らないため。
   `push:clean` は、わざと1か所だけ変えて送り、元に戻してもう一度送るので、GAS の上が手元と同じになる
6. 消えたかを確かめるときは、別の一時フォルダで `npx clasp clone <スクリプト ID> --rootDir .` を実行し、`fill-password.local.js` が無いことを見る（見終わったらフォルダごと消す）

本番に切り替えるときも同じ手順で行う（`migrate()` のあと。`SHEET_ID` などは本番のものになっている）。

## 7. ウェブアプリとして公開する・更新する

公開の設定（実行するユーザーは自分、アクセスは全員）は `gas/appsscript.json` に書いてある。URL が知られても、`API_KEY` が無ければ全部弾く。

初めて公開するとき（開発版は公開済み）

```
npx clasp create-deployment --description "v2 開発版"
```

デプロイ ID は `npx clasp list-deployments` で見られる（「v2 開発版」の行。`@HEAD` の行ではない）。公開リポジトリには書かない。

コードを直したあとは、送ってから同じデプロイを新しい版に差し替える。こうすると URL は変わらない。

```
npm run push
npx clasp create-deployment --deploymentId <デプロイ ID> --description "v2 開発版"
```

画面の接続設定には、`https://script.google.com/macros/s/<デプロイ ID>/exec` と `API_KEY` を入れる。

## 8. 画面を手元で試す

```
node scripts/dev-server.js
```

`http://localhost:8787/v2/` で新版の画面が開く。

- 接続設定に `http://localhost:8787/api` と鍵 `dev-key` を入れると、GAS のコードを模擬環境で動かした作り物のデータで試せる。Google には一切つながない
- 接続設定に本物のウェブアプリの URL と鍵を入れれば、開発用シートのデータで試せる

## 本番に切り替える（7章の手順5）

#### 10 のくわしい手順（旧版の鍵を変える）

旧版の画面は、切り替えのあとも端末の保存に残る。うっかり開いて操作しても `Sheet1` を書き換えないよう、旧版の GAS の鍵を変えて止める。
11 で一番上を差し替えると旧版の画面は開けなくなるので、確かめはその前に PC で行う。

1. 本番シートの「拡張機能 → Apps Script」で旧版の GAS を開き、`WebAppApi.gs` を開く
2. `const WA_KEY = '…';` の今の鍵を、パスワード管理アプリなどに控える（戻すときに使う。この手順書には書かない）
3. `WA_KEY` を、控えたものとは別のでたらめな文字列に書き換えて保存する（4 の `node -e …` で作れる）
4. 「デプロイ → デプロイを管理」→ 鉛筆 →「バージョン」を「新バージョン」にして「デプロイ」。URL は変わらない
5. PC のブラウザで旧版の画面（`https://tsuchikamiyudai0215-del.github.io/shukatsu/`）を開いて確かめる
   - 端末に一覧の控えがあると、古い一覧が出たうえで、上に赤く「最新を取得できませんでした」と出る。これで正しい
   - 試しに1つ操作すると「保存できませんでした：鍵が違います」と出て、シートは変わらない
   - 控えが無い端末では「読み込めませんでした。鍵が違います」と出る

#### 12 のくわしい手順（新版を本番につなぐ）

ホーム画面のアイコンから全画面で開くアプリは、Chrome や Safari とは別に、アイコンごとの保存領域を持つ。アイコンを消すと、その保存領域も消える。
旧版で画像ファイルから入れた手動ロゴ（`sk_manual_logos`）は、いつも開いていたアイコンの保存領域にある。
11 のあとは、今のアイコンから開くと同じアイコンの中で `/v2/` に移るので、新版がその保存領域で開き、手動ロゴをそのまま写せる。**ホーム画面のアイコンは消さない・置き直さない。**

スマホ

1. ホーム画面の今の「就活」のアイコンから開く。`/v2/` に移り、接続設定の画面が出る（このアイコンの中で新版を開くのは初めてなので）
2. 本番用のウェブアプリの URL と鍵を入れて「接続する」
3. 一覧が出たら、旧版で画像ファイルから入れたロゴが出ていることを見る（一覧が届いたところで、一度だけ写す）
4. アイコンを閉じて開き直し、そのまま新版が開くことを見る

PC（Chrome）

1. `https://tsuchikamiyudai0215-del.github.io/shukatsu/` を開くと `/v2/` に移る
2. 開発用につないだことがある Chrome なら、一覧が開発用のまま出る。記録タブのいちばん下「接続先を変える」から、本番用の URL と鍵を入れる。初めてなら、接続設定の画面にそのまま入れる
3. 接続先を変えると、開発用の一覧の控えと画像ファイルのロゴは捨て、旧版の手動ロゴを本番の会社で写し直す

気をつけること

- 11 の push が github.io に出る前にアイコンを開くと、旧版の画面が出る。PC で `/v2/` に移ることを見てからにする
- 圏外で開くと、差し替えたページを一度も開いていない端末では、保存してあった旧版の画面が出ることがある。つながった状態で一度開けば直る

戻したあとに残ること

- `migrate` は、結果発表の予定の説明欄からパスワードの行を消している。旧版は結果発表の予定を読まないので、困ることはない
- `syncAllCalendars` を実行していたら、旧版の予定の説明欄からもパスワードの行が消え、見出しと通知が新版の形になっている。旧版で会社を操作すると、旧版の形で書き直される
- `syncAllCalendars` は、結果待ちの会社の締切の予定と、見送り・落選の会社のこれから先の予定を消している。旧版で戻しても、この予定は作り直されない。要るものは、旧版でその会社の締切を保存し直すと作られる
- 端末に新版の保存（`sk2_` で始まるもの）が残るが、旧版は読まないので害はない
